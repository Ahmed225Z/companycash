## D-001 — تثبيت نسخ الحزم على PHP 8.2 (platform pin)
**التاريخ:** 2026-10-15 · **المرحلة:** P0.1

**المشكلة:** الـ `composer.lock` اللي كان في الريبو اتولّد على PHP أحدث — كان فيه حزم بتطلب PHP ≥ 8.3 و ≥ 8.4 (`laravel/pint v1.32.1`, `symfony/*` 8.x) بينما الـ PHP المحلي **8.2.12**. أي `composer require` كان بيفشل.

**القرار:** إضافة platform pin في `composer.json`:
```json
"config": { "platform": { "php": "8.2.12" } }
```
وعمل `composer update` كامل لإعادة حل الاعتماديات على 8.2.

**النتيجة:** Symfony رجعت لـ 7.4، و `laravel/pint` لـ 1.30.4 — كلهم متوافقين مع Laravel 12 و PHP 8.2، ومطابقين لـ `"php": "^8.2"` المعلنة في `composer.json`.

**البديل المرفوض:** ترقية PHP للـ 8.4 — تغيير أكبر في بيئة المستخدم (XAMPP) ومش مطلوب للمشروع.

**لو اتغيّر الرأي لاحقاً:** احذف الـ `platform` block واعمل `composer update` على PHP 8.4.

## D-002 — Livewire 4 بدل Livewire 3
**التاريخ:** 2026-10-15 · **المرحلة:** P0.1

**المشكلة:** المواصفات كانت بتقول Livewire 3، لكن الإصدار المستقر الحالي **4.4.7** وهو اللي اتثبّت افتراضياً.

**القرار:** الاستمرار على **Livewire 4** — المشروع جديد تماماً ومفيش كود قديم يتكسر، وبنستفيد من مميزات الإصدار الأحدث ودعم أطول.

**أثر على الأوامر:** في Livewire 4 أمر نشر الإعدادات بقى `php artisan livewire:config` بدل `livewire:publish --config`.

**تم تحديث:** جدول الستاك في `AGENT_PROMPT.md`.

## D-003 — تفعيل إضافتَي gd و intl في PHP
**التاريخ:** 2026-10-15 · **المرحلة:** P0.1

**المشكلة:** `maatwebsite/excel` (عبر PhpSpreadsheet) بيطلب `ext-gd` وكانت متعطّلة في `C:\xampp\php\php.ini`.

**القرار:** تفعيل `extension=gd` و `extension=intl` في php.ini (مع أخذ نسخة احتياطية `php.ini.bak-20261015-124638`).

- **gd:** مطلوب لـ PhpSpreadsheet و dompdf (الصور في التقارير).
- **intl:** هيتستخدم في P5.3 لتنسيق الأرقام والتواريخ والعملة بالعربي (`NumberFormatter` / `IntlDateFormatter`).

**ملاحظة:** التفعيل سرى على PHP CLI فوراً. لو المشروع هيتشغّل عبر Apache في XAMPP لازم إعادة تشغيل Apache.
